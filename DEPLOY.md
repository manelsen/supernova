# Deploy

## Quick Start

```bash
# 1. Edit supernova.yaml — add your LLM provider API key
vim supernova.yaml

# 2. Launch
docker compose up
```

## What You Need

At minimum, add a `providers` section to `supernova.yaml`:

```yaml
providers:
  openai:
    api_key: "${OPENAI_API_KEY}"   # or paste your key directly
    model: "gpt-4o-mini"
```

Then set the env var (optional — use env var or paste key directly):
```bash
export SUPERNOVA_PROVIDER_OPENAI_API_KEY=sk-...
docker compose up
```

## If the App Fails to Start

The error message tells you exactly what's missing. For example, if no LLM provider is configured:

```
❌ Failed to start services: no LLM providers configured

Add this to supernova.yaml providers section:

  providers:
    openai:
      api_key: "your-key-here"
      model: "gpt-4o-mini"

Then restart: docker compose restart
```

## Wizard Setup (for interactive first-time setup on your dev machine)

```bash
gleam run -m supernova/wizard_main
```

This generates a `supernova.yaml` configured for your channels. Copy the result into your deployment.

## Health Endpoints

Once running, the health server is on port **8080**:

| Endpoint | Purpose |
|----------|---------|
| `GET /health` | Basic status + uptime |
| `GET /health/live` | Liveness probe |
| `GET /health/ready` | Readiness probe |

Test locally:
```bash
curl http://localhost:8080/health
```

## Troubleshooting

**App crashes on startup:**
```bash
docker compose logs supernova
```

**Postgres connection issues:**
```bash
docker compose up postgres
docker compose exec postgres pg_isready -U supernova
```

## What You Need

At minimum, set **one** LLM provider key (or run the wizard to generate a config):

```bash
# Option A: Run the wizard to generate supernova.yaml
gleam run -m supernova/wizard_main

# Option B: Set env vars + a pre-existing supernova.yaml with provider defined
SUPERNOVA_OPENAI_API_KEY=sk-...
```

**Note:** `SUPERNOVA_OPENAI_API_KEY` alone won't work — the provider must already be defined in `supernova.yaml`. The wizard generates this for you.

Then configure the channels you use (optional but recommended):
```bash
SUPERNOVA_TELEGRAM_TOKEN=123456:ABC-DEF...
SUPERNOVA_DISCORD_TOKEN=your-discord-bot-token
```

```bash
SUPERNOVA_DISCORD_TOKEN=your-bot-token
```

## Architecture

```
supernova/
  .env               ← your secrets (not committed)
  supernova.yaml     ← auto-generated by wizard OR use env overrides
  docker-compose.yml ← runs app + postgres

postgres/
  postgres_data/    ← persistent storage
```

## Health Endpoints

Once running, the health server is on port **8080**:

| Endpoint | Purpose |
|----------|---------|
| `GET /health` | Basic status + uptime |
| `GET /health/live` | Liveness probe (Kubernetes) |
| `GET /health/ready` | Readiness probe (checks channels) |

Test locally:
```bash
curl http://localhost:8080/health
```

## Wizard Setup

For interactive first-time setup:
```bash
gleam run -m supernova/wizard_main
```
This generates a `supernova.yaml` configured for your channels.

## Without Wizard

The app works without `supernova.yaml` — it uses environment variable overrides. Configure channels directly in `.env`:
```bash
SUPERNOVA_TELEGRAM_TOKEN=...
SUPERNOVA_DISCORD_TOKEN=...
```

## Troubleshooting

**App crashes on startup:**
```bash
docker compose logs supernova
```

**Health check failing:**
```bash
docker compose exec supernova wget -qO- http://localhost:8080/health/live
```

**Postgres connection issues:**
```bash
docker compose up postgres
docker compose exec postgres pg_isready -U supernova
```
